## 1. Current SVG-to-Execution Pipeline

```
SVG file on disk
    │
    ▼
parse_svg_path.py — parse_svg_for_paths()
    │  reads SVG file, extracts path "d" attributes
    │  produces (N, 3) array: XY in SVG user units, Z = 0 pen-down / Z = 0.05 pen-up
    ▼
parse_svg_path.py — scale_coords_to_arena()
    │  rearranges axes (SVG Y-down → robot frame), uniform scale to dx × dy
    │  shifts X origin, adds z_min offset
    │  produces (N, 3) in arena coordinates
    ▼
trajectory.py — SvgTrajectory
    │  wraps parse + scale, validates shape/finiteness
    │  exposes .positions_m as (N, 3) ndarray
    ▼
pen_tip_kinematics.py — legacy_positions_to_pen_tip()
    │  subtracts LEGACY_IMPLICIT_PEN_LENGTH_M (0.110) from Z
    │  converts flange-height coordinates to pen-tip coordinates
    │  Z = 0.525 (write), Z = 0.575 (pen-up)
    ▼
contact_dynamics.py — fit_xy_path_to_surface()
    │  uniform scale preserving aspect ratio
    │  centers XY on notebook (0.45, 0.0)
    │  respects margin_m on all sides
    │  Z unchanged
    ▼
contact_dynamics.py — apply_write_preload()
    │  lowers Z at write height by preload_depth_m (0.0005)
    │  Z = 0.5245 (write), Z = 0.575 (pen-up)
    ▼
writing_plan.py — TimedWritingPlan
    │  consumes svg_positions_m: (N, 3) ndarray
    │  classifies transitions as APPROACH/LOWER/WRITE/LIFT/TRANSFER/RETREAT
    │  generates minimum-jerk Cartesian segments
    ▼
tasks/writing_studio.py — WritingStudioTask
    │  orchestrates plan() → validate() → run()
    │  validates workcell bounds, sampled IK reachability, collision preflight
    ▼
robot/interface.py — RobotInterface
    │  authoritative state machine: INIT → HOMING → READY → PLANNING → VALIDATING → EXECUTING → COMPLETE
    │  cooperative STOP, RESET, fault handling
    ▼
experiments/writing_experiment.py — WritingExperiment.run()
    │  hybrid Cartesian controller: XY position + Z force admittance + orientation hold
    │  damped least-squares differential IK
    │  PyBullet simulation loop with telemetry
    ▼
simulation/pybullet_adapter.py — PyBulletAdapter
```

**Key observation:** `TimedWritingPlan` consumes a plain `(N, 3)` numpy array (`svg_positions_m` parameter). The SVG-specific processing is entirely upstream. This is the natural architectural seam for generalization.

## 3. Proposed DrawingDocument Architecture

### Domain model

```python
@dataclass(frozen=True)
class Stroke:
    """One continuous pen-down path in 2D drawing space."""
    points: np.ndarray  # (M, 2) — 2D source coordinates

@dataclass(frozen=True)
class DrawingDocument:
    """Input-source-independent multi-stroke drawing."""
    strokes: tuple[Stroke, ...]
    source: str              # "svg", "touchpad", "api"
    canvas_size: tuple[float, float] | None = None
```

### Design rationale

1. **Strokes are preserved** — pen-up transfers between strokes are explicit, not encoded as Z-jumps.
2. **2D only** — Z is a robot/workcell concern, not a drawing concern.
3. **Unitless at this layer** — coordinate mapping to physical notebook is a separate explicit step.
4. **Both inputs produce it** — SVG adapter extracts strokes from path data; touchpad captures them directly.
5. **Deterministic downstream** — `drawing_to_waypoints()` converts to the existing `(N, 3)` format with explicit pen-lift/lower Z transitions.

### Conversion function

```python
def drawing_to_waypoints(
    document: DrawingDocument,
    *,
    surface_height_m: float,
    lift_clearance_m: float = 0.05,
) -> np.ndarray:
    """Convert drawing strokes to (N, 3) Cartesian pen-tip waypoints.

    Z = surface_height_m for pen-on-paper (WRITE)
    Z = surface_height_m + lift_clearance_m for pen-up (TRANSFER)
    """
```

Output feeds directly into the existing `fit_xy_path_to_surface()` → `apply_write_preload()` → `TimedWritingPlan` chain.

### Dependency graph change

**Before (v1.0.0):**

```
SVG File → parse_svg_path → SvgTrajectory → WritingExperiment → TimedWritingPlan → WritingStudioTask → RobotInterface → PyBullet
```

**After (v1.1.0):**

```
SVG File ─── svg_adapter ──→ DrawingDocument ─→ drawing_to_waypoints() ─→ fit_xy_path_to_surface ─→ apply_write_preload ─→ TimedWritingPlan ─→ (unchanged)
Drawing Pad ────────────────↗
```

Everything from `TimedWritingPlan` rightward is unchanged.

### Thread boundary invariant

```
GUI thread                    │  Worker thread
                              │
DrawingPad → DrawingDocument ─┼─→ ExperimentWorker
                              │   → ExperimentConfig(drawing=...)
                              │   → RobotInterface
                              │   → WritingStudioTask
                              │   → WritingExperiment
                              │   → drawing_to_waypoints()
                              │   → TimedWritingPlan
                              │   → PyBullet loop
                              │
Qt signals ← telemetry ───────┤
```

No robot control crosses the thread boundary. The GUI only provides data and receives status.

## 6. Compatibility Risks

| Risk | Severity | Mitigation |
|------|----------|------------|
| `ExperimentConfig.svg_file` validated with `.is_file()` | Medium | Skip file check when `drawing` is provided |
| `WritingExperiment.__init__` creates `SvgTrajectory` unconditionally | Medium | Guard with `if config.drawing is None` |
| `SvgTrajectory.metadata()` used in experiment summary logging | Low | Drawing source provides its own `metadata()` |
| `trajectory.py` tests assume SVG file existence | None | SVG tests unchanged; parallel drawing tests added |
| `./wr ui` command behavior | Low | Preserved — launches new dashboard which subsumes old one |
| `ExperimentWorker` takes `svg_file` as required | Medium | Make optional when `drawing` provided |
| `ExperimentConfig` frozen dataclass gains new field | Low | Default `drawing=None` preserves all existing callers |
| Existing CLI `--svg` flag | None | Unchanged; CLI always uses SVG path |
